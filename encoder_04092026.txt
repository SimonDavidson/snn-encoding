  θ_c[n] = θ_0 + a_c[n]                                   (22)
  a_c[n] = ρ·a_c[n-1] + Δ_a·s_c[n-1],   ρ = exp(-dt/τ_a)   (23)

  rather than duplicating it".

  Proposed change

  One file changes: src/spikeenc/encoders.py.

  1. Generalise _integrate_and_fire to carry the adaptive threshold: extra args
     delta_a, tau_a; theta becomes the baseline θ₀; returns a threshold trace
     alongside the v trace. Loop body becomes, in this order:

  a     = rho * a + delta_a * fired      # `fired` is s[n-1] — same one-step lag
  as the reset
  thr   = theta_0 + a
  v     = beta * v * ~fired + (1-beta) * gain * drive[:, i]
  fired = v >= thr
     a starts at zeros, so thr[:,0] == theta_0 and there is no startup
     transient.
  2. LIF routes through the same call with delta_a=0.0. This is the point:
     rho*0.0 + 0.0*s is exactly 0.0, and theta_0 + 0.0 is exactly theta_0, so E1
     and E4-at-Δ_a=0 execute the same instructions on the same values — T4.1
     then holds by construction rather than by numerical luck. It does mean E1's
     code path moves, so I will prove the refactor bit-identical on a batch of
     cases (constant / step / sine / noise drive, several θ, τ_m, gain,
     refractory>0 and =0) by comparing channel, time and polarity arrays exactly
     against the current commit before committing. Same control I used for the
     D30 sharing.
  3. ALIF.encode_from_drive implemented as a thin wrapper: unipolar +1 polarity
     like E1, state keys "v" and "threshold". LIF keeps returning only "v",
     which is what SPEC §4.2 lists.
  4. Module docstring STATUS: line and Last modified: date updated.

  Not touched: tests/, SPEC.md, conftest.py, .github/. Scratch verification
  script goes in the session scratchpad, uncommitted.

  One judgement call I want to flag

  Refractory × adaptation. During an absolute refractory period D17 clamps v and
  discards drive. My reading is that a should keep decaying through it and
  simply not be incremented (no spike, so s[n-1]=0) — adaptation is a threshold
